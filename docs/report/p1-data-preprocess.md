## 1.1 ขนาดเหรียญจริง

ระบบไม่ต้องรู้สเกลของภาพล่วงหน้า แต่ใช้อัตราส่วนขนาดระหว่างเหรียญในภาพเดียวกัน (หัวข้อ 1 ของแผน) จึงต้องรู้ขนาดจริงของแต่ละชนิด

## 1.3 ป้ายกำกับและการแบ่งชุดข้อมูล

### ป้ายกำกับ

หนึ่งภาพมีไฟล์ JSON หนึ่งไฟล์ เก็บวงกลม (`center_xy`, `radius_px`) และชนิด (`coin_type`) ของทุกเหรียญ
พิกัดเป็นพิกเซลของภาพเต็มหลังหมุนตาม EXIF (รูปแบบเต็มใน `docs/labels.md`)

- วาดวงเองทุกเหรียญด้วย `data/label_tool.py` **ไม่ใช้ผลของระบบเป็นจุดเริ่ม** เพราะป้ายใช้วัดผลระบบ ถ้าเริ่มจากผลระบบ
  ป้ายจะเอนเข้าหาความผิดพลาดของระบบ
- ภาพเอียงใช้ครึ่งหนึ่งของแกนยาวเป็นรัศมี (ตรงกับที่ส่วนที่ 2 ใช้แกนยาวของวงรีเป็นเส้นผ่านศูนย์กลาง)
- เหรียญที่ซ้อนหรือล้นขอบภาพจนเห็นไม่ถึงครึ่งไม่ต้องใส่

### การแบ่งชุด

| ชุด | ใช้ทำอะไร | จำนวนภาพ |
|---|---|---|
| `tune` | ปรับค่าและเลือกวิธีของทุกส่วน | 84 |
| `test` | วัดผลสุดท้าย **ล็อกแล้ว ห้ามใช้ปรับค่า** | 43 |
| `web` | วัดผลบนภาพที่ไม่ได้ถ่ายตามโปรโตคอล ห้ามใช้ปรับค่า | 8 |
| `synth` | ทดลองการจำแนก | 18 |

`python data/dataset.py split` แบ่งภาพของทีมเข้า test 30% โดย

- **แบ่งตามกลุ่มเงื่อนไข** (พื้นหลัง, แสง, มุม) ให้ทุกเงื่อนไขอยู่ในชุด test
- **แบ่งตามฉาก** ภาพที่ถ่ายห่างกันไม่เกิน 6 วินาที (จาก EXIF) นับเป็นฉากเดียวกันและต้องอยู่ชุดเดียวกัน
  ป้องกันภาพที่แทบซ้ำกันกระจายไปทั้ง tune และ test
- **ตัดสินด้วย hash ของชื่อไฟล์** รันกี่ครั้งก็ได้ผลเดิม และภาพที่อยู่ในไฟล์แล้วไม่ถูกย้าย

ฉากที่เครื่องมือแยกไม่ได้ต้องตรวจด้วยตา เช่น `cloth_room_tilt15_124–125` กับ `126–127` ถ่ายห่างกัน 28 วินาที
เครื่องมือนับเป็นคนละฉาก แต่เป็นเหรียญชุดเดียวกันจัดวางใหม่ จึงย้ายทั้งสี่ภาพไปอยู่ชุด tune ก่อนล็อก

## 1.4 การปรับปรุงภาพ (`preprocess`)

```
preprocess(image) -> PreprocessResult
```

รับภาพ BGR ที่หมุนตาม EXIF แล้ว (backend หมุนตอนอ่านไฟล์) คืนภาพสี ภาพเทาที่ปรับแล้ว สเกลที่ย่อ สถานะ และเหตุผล

| ขั้น | ทำอะไร | เหตุผล |
|---|---|---|
| 1. ย่อภาพ | ด้านยาวเหลือ 1600 px ด้วย `INTER_AREA` (ไม่ขยายภาพเล็ก) | ภาพมือถือ 12–24 MP ช้าเกินไป และเวลาทุกขั้นถัดไปขึ้นกับขนาดภาพ `INTER_AREA` เฉลี่ยพิกเซลจึงไม่เกิดลายเมื่อย่อ |
| 2. ตรวจคุณภาพ | หัวข้อ 1.5 | ตรวจจากภาพเทาก่อนปรับใด ๆ เพื่อให้เห็นแสงจริงของภาพ |
| 3. ภาพเทา | `cvtColor(BGR2GRAY)` | ส่วนที่ 2 หาเหรียญจากภาพเทา |
| 4. เพิ่มความต่าง | CLAHE (clip 2.0, ช่อง 8×8) | เพิ่มความต่างระหว่างเหรียญกับพื้นทีละบริเวณ (ดูผลทดลองหัวข้อ 1.6) |
| 5. ลดจุดรบกวน | median filter 5×5 | ลดจุดรบกวนและลายเล็กของพื้นโดยไม่ทำให้ขอบเหรียญเบลอเท่า Gaussian |

**ภาพสีไม่ถูกปรับ** ส่วนที่ 3 วัดสี HSV จากภาพสีที่ย่อแล้วเท่านั้น ถ้าปรับความต่างในภาพสี สีของเหรียญทอง เงิน
และทองแดงจะเพี้ยน `white_balance` (gray world) มีไว้สำหรับการทดลองเท่านั้น

ภาพที่ไม่ผ่านการตรวจคุณภาพยังคืนภาพทุกขั้นไว้ (`debug_images`) ให้หน้า "เกี่ยวกับ" แสดงได้

## 1.5 การตรวจคุณภาพภาพ

ตรวจตามลำดับจากปัญหาที่แก้ง่ายที่สุด เจอข้อแรกที่ไม่ผ่านก็หยุด แล้วคืน `status="failed"` พร้อมเหตุผลภาษาไทยที่บอกผู้ใช้ว่าต้องทำอะไร

| ตรวจ | วัดอะไร (ภาพเทาหลังย่อ) | เกณฑ์ไม่ผ่าน | ข้อความถึงผู้ใช้ |
|---|---|---|---|
| ภาพเล็ก | ด้านสั้น | < 480 px | ภาพเล็กเกินไป กรุณาใช้ภาพที่ด้านสั้นอย่างน้อย 480 พิกเซล… |
| มืด | เปอร์เซ็นไทล์ 99 ของความสว่าง | < 80 | ภาพมืดเกินไป กรุณาเปิดไฟหรือถ่ายในที่สว่างขึ้น |
| สว่างเกิน | สัดส่วนพิกเซล ≥ 250 | > 60% | ภาพสว่างเกินไป กรุณาหลบแสงจ้าหรือปิดแฟลช |
| ไม่มีรายละเอียด | สัดส่วนพิกเซลที่ Sobel ≥ 60 | < 0.05% | ไม่พบรายละเอียดในภาพ… |
| เบลอ | min(var ∂²/∂x², var ∂²/∂y²) บนขอบที่แรงสุด 2% | < 100 | ภาพเบลอ กรุณาถือกล้องให้นิ่งและแตะหน้าจอให้โฟกัสที่เหรียญก่อนถ่าย |

เหตุผลของการออกแบบ

- **มืด:** ใช้ส่วนที่สว่างที่สุดของภาพ ไม่ใช้ค่าเฉลี่ย เพราะเหรียญบนผ้าสีเข้มมีค่าเฉลี่ยต่ำแต่เหรียญยังสว่างชัด
- **เบลอ:** วัดเฉพาะบริเวณขอบ เพราะพื้นเรียบกินพื้นที่ส่วนใหญ่ ถ้าวัดทั้งภาพ ภาพคมก็ได้ค่าต่ำ และแยกแนวนอนกับแนวตั้ง
  แล้วใช้ค่าที่ต่ำกว่า เพราะมือสั่นทำให้เบลอทางเดียว (Laplacian รวมสองแนวยังสูงจากขอบแนวที่คมอยู่)
- **ไม่มีรายละเอียด:** เดิมใช้ความแรงขอบที่เปอร์เซ็นไทล์ 98 แต่ภาพเหรียญเดียวบนกระดาษขาวมีขอบไม่ถึง 2% ของภาพ
  ค่าจึงไปวัดที่พื้นกระดาษ ภาพเหรียญเดี่ยว (13–14) ได้ค่าต่ำกว่ากระดาษเปล่าจริง (14–17) และถูกปฏิเสธผิด 4 ภาพในชุด tune
  จึงเปลี่ยนเป็นนับสัดส่วนพิกเซลที่ขอบแรง ภาพที่มีเหรียญได้ ≥ 0.32% กระดาษเปล่าจริง (ตัดจากส่วนที่ไม่มีเหรียญ) ≤ 0.007%
  ตั้งเกณฑ์ 0.05% ห่างจากทั้งสองฝั่ง

## 1.6 การทดลอง: Histogram Equalization / CLAHE / White balance

**คำถาม:** การปรับภาพแต่ละแบบช่วยการหาเหรียญและการจัดกลุ่มสีหรือไม่

**วิธี** (`data/preprocess_experiment.py`) รันทุกวิธีบนภาพเดียวกัน วัดสองเรื่องแยกกัน

- หาเหรียญ: `detect_coins` จริงของส่วนที่ 2 บนภาพเทาที่ปรับแล้ว จับคู่กับป้ายเมื่อจุดศูนย์กลางห่างไม่เกินครึ่งรัศมี
- จัดกลุ่มสี/ชนิด: `classify_coins` จริงของส่วนที่ 3 บน**วงกลมจากป้ายกำกับ** ตัดผลของการหาเหรียญออก จะได้เห็นผลของ
  white balance ต่อสีอย่างเดียว

**เลือกวิธีจากชุด tune เท่านั้น** ผลชุด web รายงานอย่างเดียว

### ผลบนชุด tune (84 ภาพ, detection หลัง PR #36)

| วิธี | Det P % | Det R % | คลาดรัศมี % | กลุ่มสีถูก % | ชนิดถูก % | เวลา (ms) |
|---|---|---|---|---|---|---|
| ไม่ปรับ (`none`) | **67.0** | **64.1** | 10.3 | 57.2 | 27.2 | 47.1 |
| HE | 22.2 | 37.0 | 12.5 | 57.2 | 27.2 | 48.0 |
| CLAHE | 54.0 | 62.2 | **9.9** | 57.2 | 27.2 | 48.7 |
| CLAHE + white balance | 52.3 | 60.1 | **9.9** | **59.9** | **27.6** | 101.8 |

ภาพที่ถูกปฏิเสธนับเหรียญในภาพเป็นเหรียญที่หาไม่เจอใน Det R ค่าอื่นคิดเฉพาะภาพที่ผ่าน

ผลทั้งไปป์ไลน์ (`eval/run_eval.py --split tune`, วิธี color+scale+template) เมื่อเปลี่ยนแค่ค่า `enhance`:

| ตัวชี้วัด | CLAHE | ไม่ปรับ |
|---|---|---|
| Acc รายเหรียญ | 0.196 | **0.221** |
| MAE ยอดรวม (บาท) | 7.33 | **5.83** |
| ยอดถูกพอดี % | 7.1 | **9.5** |
| ภาพที่ล้มเหลว % | 4.8 | **3.6** |

### สรุปผล

1. **การเพิ่มความต่างไม่ได้ช่วยการหาเหรียญ** ไม่ปรับให้ Precision สูงกว่า CLAHE 13 จุดและ Recall สูงกว่าเล็กน้อย
   เพราะ CLAHE ดึงลายพื้นผ้าและลายบนผิวเหรียญให้ชัดขึ้น ตัวหาเหรียญจึงจับลายผ้าเป็นเหรียญมากขึ้น HE ปรับทั้งภาพด้วย
   ฮิสโทแกรมเดียวจึงแย่ที่สุด ข้อเสียของการไม่ปรับมีอย่างเดียวคือความคลาดรัศมีสูงกว่า CLAHE เล็กน้อย (10.3% vs 9.9%)
2. **ผลดีขึ้นต่อทั้งไปป์ไลน์** ส่วนที่ 3 ใช้ภาพเทาเดียวกันใน template matching การไม่ปรับจึงทำให้การจำแนกและยอดรวมดีขึ้นด้วย
3. **white balance ช่วยกลุ่มสีเล็กน้อยบนชุด tune** (57.2% → 59.9%) แต่การหาเหรียญแย่ลงเล็กน้อย เวลาเพิ่มเป็นสองเท่า
   และ gray world สมมติว่าค่าเฉลี่ยทั้งภาพเป็นสีเทา ซึ่งไม่จริงเมื่อพื้นหลังมีสีเด่น จึงไม่เปิดเป็นค่าเริ่มต้น
   (บนชุด web ที่รายงานอย่างเดียว กลุ่มสีลดจาก 73.4% เหลือ 21.9% สอดคล้องกับข้อจำกัดนี้)
4. HE และ CLAHE ไม่เปลี่ยนผลกลุ่มสีเลย เพราะปรับเฉพาะภาพเทา ส่วนที่ 3 อ่านสีจากภาพสี

> **ยังต้องตัดสินร่วมกับส่วนที่ 2** (เสนอใน #34): ผลชี้ว่าควรเปลี่ยนค่าเริ่มต้นจาก CLAHE เป็นไม่ปรับ แต่ค่าเกณฑ์ของ
> ตัวหาเหรียญถูกจูนมากับภาพหลัง CLAHE ระบบตอนนี้จึงยังใช้ CLAHE อยู่จนกว่าจะตกลงกัน

## 1.7 ข้อจำกัด

- **พื้นหลังมีแค่ 2 แบบ** (ผ้าสีเข้ม กระดาษขาว) ไม่มีโต๊ะไม้หรือพื้นสีใกล้เหรียญทอง ผลบนพื้นแบบอื่นจึงยังไม่ได้ทดสอบ
- **แสงเกือบทั้งหมดเป็นแสงห้อง** มีภาพแฟลชแค่ 2 ภาพ และมุมเอียง 30° แค่ 6 ภาพ
- **เหรียญ 2 บาทมีน้อย** (เหรียญจริง 32 ครั้งที่ปรากฏ จากเหรียญไม่กี่เหรียญที่ถ่ายซ้ำ) ความแม่นของ 2 บาทจึงมีความไม่แน่นอนสูง
- **ภาพเว็บมีแค่ 8 ภาพ และครึ่งหนึ่งเล็กเกินเกณฑ์** ชุด web ที่ใช้วัดผลได้จริงจึงเหลือ 4 ภาพ
  และหาแหล่งที่มาเดิม (URL, วันที่) ของภาพเว็บไม่ได้แล้ว
- **เกณฑ์ตรวจคุณภาพตั้งจากชุด tune ที่ไม่มีภาพเสียจริงหลายประเภท** ภาพเบลอจริงมี 3 ภาพ ส่วนภาพมืด สว่างเกิน
  และพื้นเปล่าทดสอบด้วยภาพสังเคราะห์และภาพตัดจากภาพจริงในเทสต์ (`backend/tests/test_preprocess.py`)
- **ภาพเหรียญทุกเหรียญมาจากเหรียญชุดเดียวกันของทีม** แม้แบ่งชุดตามฉากแล้ว เหรียญเหรียญเดียวกันยังปรากฏทั้งใน tune และ test
